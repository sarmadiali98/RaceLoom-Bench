## Branch signature and `BSw` semantics (verified)

`CBg:12;CIngress:1;CWaypoint:1;BSw:15` — 12 background-update components (`CBg:12`, one per
churn level), 1 ingress component (`CIngress:1`), 1 waypoint component (`CWaypoint:1`) and
15 switch components (`BSw:15`), at depth 4 with BFS. This matches the committed encoding,
`docs/final_4x4_matrix.tsv`, and both 2026-06-05 logs.

`BSw` counts the alternatives of the generated `BSWMain` recursive definition — the
big-switch expression that the RaceLoom model builder emits for the network's switches. It
is generated by `DNKMaudeModel.__buildBigSwMainExpr` in the RaceLoom implementation, which
is distributed separately from RaceLoom-Bench and is not tracked in this repository (so no
repository-relative source link is given; see *Implementation provenance for `BSw`* below).
The generated expression starts from one base default-forwarding alternative and appends one
alternative per `DirectUpdate` and one per `RequestedUpdate` across all switches.
`InitialFlowTable` entries are **not** counted by `BSw`; in particular, the destination
switch's initial forwarding table contributes nothing, and the faulty/control difference at
the waypoint `SW009` `InitialFlowTable` (see *Faulty / control distinction* above) leaves
`BSw` unchanged. The `Links` expression is not counted either; in this instance
`bad/model.json` and `control/model.json` have identical `Links`, so no link-related
alternatives arise in either model.

The committed K12 models (`bad/model.json` and `control/model.json` are identical in this
respect) contain exactly 14 `DirectUpdate`s and zero `RequestedUpdate`s:

| Contribution | Count |
|---|---:|
| Base default-forwarding alternative | 1 |
| Background `DirectUpdate`s — K = 12, one per background switch (`SW001`, `SW002`, `SW004`, `SW005`, `SW006`, `SW011`, `SW015`, `SW016`, `SW019`, `SW020`, `SW022`, `SW023`) | 12 |
| Ingress `DirectUpdate` (`SW026`, channel `upIngress`) | 1 |
| Waypoint `DirectUpdate` (`SW009`, channel `upWaypoint`) | 1 |
| Destination `DirectUpdate`s (`SW008` has none) | 0 |
| `RequestedUpdate`s | 0 |
| **`BSw` total** | **15** |

so `BSw = 1 + 12 + 1 + 1 + 0 + 0 = 15`, matching the historical signature `BSw:15` in both
logs. The 12 background switches and the core placement (source `SW026`, waypoint `SW009`,
destination `SW008`) are recorded in `source/churn_embedding.json`.
