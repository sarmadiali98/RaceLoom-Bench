## Branch signature and `BSw` semantics (verified)

`CBg:8;CIngress:1;CWaypoint:1;BSw:11` — 8 background-update components (`CBg:8`, one per
churn level), 1 ingress component (`CIngress:1`), 1 waypoint component (`CWaypoint:1`) and
11 switch components (`BSw:11`), at depth 5 with BFS. This matches the committed encoding,
`docs/final_4x4_matrix.tsv`, and both 2026-06-02 logs.

`BSw` counts the alternatives of the generated `BSWMain` recursive definition — the
big-switch expression that the RaceLoom model builder emits for the network's switches. It
is generated by `DNKMaudeModel.__buildBigSwMainExpr` in the RaceLoom implementation, which
is distributed separately from RaceLoom-Bench and is not tracked in this repository (so no
repository-relative source link is given; see *Implementation provenance for `BSw`* below).
The generated expression starts from one base default-forwarding alternative and appends one
alternative per `DirectUpdate` and one per `RequestedUpdate` across all switches.
`InitialFlowTable` entries are **not** counted by `BSw`; in particular, the destination
switch's initial forwarding table contributes nothing, and the faulty/control difference at
the waypoint `InitialFlowTable` leaves `BSw` unchanged. The `Links` expression is not counted
either; consequently the duplicated background-link `(port = 90x1) . (port <- 90x2)` pairs in
`control/model.json` (noted above) add no `BSw` alternatives.

The committed K8 models (`bad/model.json` and `control/model.json` are identical in this
respect) contain exactly 10 `DirectUpdate`s and zero `RequestedUpdate`s:

| Contribution | Count |
|---|---:|
| Base default-forwarding alternative | 1 |
| Background `DirectUpdate`s — K = 8, one per background switch (`SW001`, `SW002`, `SW003`, `SW005`, `SW006`, `SW007`, `SW008`, `SW010`) | 8 |
| Ingress `DirectUpdate` (`SW009`) | 1 |
| Waypoint `DirectUpdate` (`SW013`) | 1 |
| Destination `DirectUpdate`s (`SW004` has none) | 0 |
| `RequestedUpdate`s | 0 |
| **`BSw` total** | **11** |

so `BSw = 1 + 8 + 1 + 1 + 0 + 0 = 11`, matching the historical signature `BSw:11` in both
logs. The superseded CMon block below carries `BSw:10`; that value belongs to the older CMon
model encoding, is retained verbatim as superseded historical evidence, and is not the
current encoding's switch-component count.
