## Faulty / control distinction

The faulty (`bad/model.json`) and control (`control/model.json`) models differ in exactly one
semantic location, the waypoint switch `SW023.InitialFlowTable`: `(port = 8502) . (port <- 8510)`
(faulty, initially forwards monitored traffic uninspected) versus
`(port = 8502) . (port <- 8503)` (control, safe from the start). In both models the waypoint's
post-update policy is the safe rewrite `(port = 8502) . (port <- 8503)`
(`upWaypoint` under `SW023.DirectUpdates`). `properties.json` is byte-identical between the two
models, SHA-256 `3fd72e9a9f97b09213799cf636b35f4b914af54cdd01f0c1bd8bd01fd962df95`.

## Branch signature

`CBg:14;CIngress:1;CWaypoint:1;BSw:17` — 14 background-update components (K=14), 1 ingress, 1
waypoint, and 17 switch components, at depth 4 with BFS. This matches the committed encoding and
`docs/final_4x4_matrix.tsv`. The historical logs print the same components in the order
`CIngress:1;CWaypoint:1;CBg:14;BSw:17`; the ordering differs but the multiset of components is
identical.

`BSw:17` is used exactly as recorded in both historical logs, and its composition is now
verified. `BSw` counts the alternatives of the big-switch expression generated by
`DNKMaudeModel.__buildBigSwMainExpr` in the RaceLoom implementation, which is distributed
separately from RaceLoom-Bench and is not tracked in this repository (so no
repository-relative source link is given). Implementation reference: Zenodo record
`16884345`; archive size 794,997,198 bytes, MD5 `21ba15ae55de83d833a80c27b677e80e`,
SHA-256 `bc533c637a0fa55e51f6c84c07137bdd44ddbd303c9a2443ab6301710ec58d45`; source file
`src/model/dnk_maude_model.py`, class `DNKMaudeModel`, function `__buildBigSwMainExpr`
(lines 177–209; the `BSw` branch count is recorded at line 208). The generated expression
starts from one base default-forwarding alternative and appends one alternative per
`DirectUpdate` and one per `RequestedUpdate` across all switches; `InitialFlowTable` entries
are not counted. The committed K14 models contain 14 background `DirectUpdate`s (one per
background switch `SW001`–`SW003`, `SW005`–`SW015`, at K=14), one ingress `DirectUpdate`
(`SW028`), one waypoint `DirectUpdate` (`SW023`), zero destination `DirectUpdate`s (`SW004`
has none), and zero `RequestedUpdate`s, so `BSw = 1 + 14 + 1 + 1 + 0 + 0 = 17`. The faulty
and control models have identical `BSw` counts; their single semantic difference (the
waypoint `InitialFlowTable`, see above) is not counted by `BSw`. An earlier audit note
described the model as containing "16 background-update switch channels"; that was a
miscount — 16 is the total number of `DirectUpdate`s (14 background + ingress + waypoint),
not the number of background channels — and the question is now resolved here rather than
left open.

## Provenance limitations

- The 2026-06-05 validation logs contain no model hash and therefore cannot be tied
  cryptographically to the committed `bad/model.json` / `control/model.json`. The historical
  match is by encoding signature (CIngress/CWaypoint/CBg, branch signature above) and by the
  documented faulty/control `InitialFlowTable` difference, not by a hash. The 2026-11-04
  reproduction closes this gap for the current commit via its provenance record; it does not
  retroactively hash-link the historical logs.
- The historical logs reference the model/property paths under the older directory name
  `benchmarks_comprehensive_topologies/b1_waypoint_order_churn/...`; the committed tree is
  `benchmarks/final/b1_waypoint_order_churn/...`. The rename is not recorded inside the logs.
- The `RaceLoom finished with exit code: 0` lines were appended by a historical progress
  wrapper; the appended line does not affect the reported statistics.
- The Geant2012 topology edge list is committed at this path: `source/topology.json` is
  present and is a byte-exact copy of the committed asset `topology_assets/T3_geant2012.json`
  (SHA-256 of both files:
  `55d8e723c57158d2472d35326741f9919e4ae8d63a39fc2144a983f36d063bfe`). Its graph statistics
  were independently recomputed from the committed file: 40 nodes, 61 undirected edges,
  connected, diameter 8, cycle rank 22, matching the asset's `stats` block and the
  `topology_stats` in `source/churn_embedding.json`. The committed generator deterministically
  derives the K14 core-link rules from the topology asset. Remaining limitation: the model
  files (`bad/model.json`, `control/model.json`) use anonymous port identifiers rather than
  topology node names, so node identity is established through the topology asset plus the
  deterministic generator, not directly from the model text. Detailed topology provenance
  (dataset, source, DOI, license) is in the README's *Topology provenance* section.
