## Branch signature and `BSw` semantics (verified)

`CBg:16;CIngress:1;CWaypoint:1;BSw:19` — 16 background-update components (`CBg:16`, one per
churn level), 1 ingress component (`CIngress:1`), 1 waypoint component (`CWaypoint:1`) and
19 switch components (`BSw:19`), at depth 4 with BFS. This matches the committed encoding,
`docs/final_4x4_matrix.tsv`, and both 2026-06-05 logs.

`BSw` counts the alternatives of the generated `BSWMain` recursive definition — the
big-switch expression that the RaceLoom model builder emits for the network's switches. It
is generated by `DNKMaudeModel.__buildBigSwMainExpr` in the RaceLoom implementation, which
is distributed separately from RaceLoom-Bench and is not tracked in this repository (so no
repository-relative source link is given; see *Implementation provenance for `BSw`* below).
The generated expression starts from one base default-forwarding alternative and appends one
alternative per `DirectUpdate` and one per `RequestedUpdate` across all switches.
`InitialFlowTable` entries are **not** counted by `BSw`; in particular, the destination
switch's initial forwarding table contributes nothing, and the faulty/control difference at
the waypoint `SW006` `InitialFlowTable` (see above) leaves `BSw` unchanged. The `Links`
expression is not counted either; in this instance `bad/model.json` and `control/model.json`
have identical `Links`, so no link-related alternatives arise in either model.

The committed K16 models (`bad/model.json` and `control/model.json` are identical in this
respect) contain exactly 18 `DirectUpdate`s and zero `RequestedUpdate`s:

| Contribution | Count |
|---|---:|
| Base default-forwarding alternative | 1 |
| Background `DirectUpdate`s — K = 16, one per background switch (`SW001`, `SW003`, `SW004`, `SW005`, `SW007`, `SW009`, `SW010`, `SW011`, `SW012`, `SW014`, `SW015`, `SW017`, `SW018`, `SW022`, `SW023`, `SW025`) | 16 |
| Ingress `DirectUpdate` (`SW048`, channel `upIngress`) | 1 |
| Waypoint `DirectUpdate` (`SW006`, channel `upWaypoint`) | 1 |
| Destination `DirectUpdate`s (`SW020` has none) | 0 |
| `RequestedUpdate`s | 0 |
| **`BSw` total** | **19** |

so `BSw = 1 + 16 + 1 + 1 + 0 + 0 = 19`, matching the historical signature `BSw:19` in both
logs. The 16 background switches and the core placement (source `SW048`, waypoint `SW006`,
destination `SW020`) are recorded in `source/churn_embedding.json`.
